OpenMAIC 企业二开 PRD 会议评审版

文档版本：v0.1 · 会议讨论稿 · 2026-07-01
来源文档：docs/PRD.md v0.4、docs/technical-design.md v0.4、docs/plan/ 切片计划。本文用于评审讨论，不替代正式主人文档。

产品定位 企业课程生成、发布、学习、测评、阶段考核和数据看板平台。
目标用户 企业管理员、企业学员、宿主系统后端/前端。
核心原则 OpenMAIC 后端为权威数据源；宿主只提供入口和查询。
开发起点 从 SLICE-00 基础设施开始，再进入账号、后端 API 和课程发布。
本文按常见 PRD 模板重组：先说明背景、目标、用户、范围、假设依赖，再进入需求表、验收标准、风险和开放问题。正式需求编号仍沿用 REQ-ID，便于和技术设计、开发计划追踪。

2. 背景与问题

问题 现状 影响
数据不共享 课程、媒体、作答和学习进度主要存在浏览器 IndexedDB。 换账号、浏览器或设备后无法形成企业级学习记录和看板。
企业管理能力缺失 缺少自有账号、角色、邀请码、课程可见范围、发布状态和后台管理。 无法按岗位分发课程，也无法管理学员和课程生命周期。
培训闭环不足 缺少强制课后测评、测评失败重学和阶段综合考核。 无法证明学习完成质量，培训结果难以量化。
宿主集成边界不清 宿主需要统一入口和看板，但不应直接依赖 OpenMAIC 数据库结构。 如果直接耦合数据库或前端消息，后续维护风险高。
编辑能力不应重复建设 OpenMAIC 已有大纲确认、Pro Mode、AI 编辑助手和 quiz 能力。 如果新增平行编辑器，会增加研发成本和一致性风险。

3. 目标与非目标

类型 内容 判断标准
目标 OpenMAIC 自带轻量企业后台和账号体系。 管理员可管理角色、邀请码、用户角色、分类、课程、考核策略和看板。
目标 课程从生成到发布、学习、测评、考核形成闭环。 学员只能看到已发布且对自己角色可见的课程；完成课程后必须测评。
目标 正式数据以后端为权威。 课程、进度、测评、考核和看板数据来自 PostgreSQL/OSS，而不是浏览器缓存。
目标 宿主系统可安全嵌入和查询。 宿主通过 SSO 进入管理员入口，通过服务端 API Key 查询看板数据。
非目标 多租户、组织树、部门可见、指定用户可见。 首版只做单租户、单角色、全体可见或按角色可见。
非目标 短信验证码、找回密码、复杂账号风控。 首版只做手机号、密码、邀请码注册登录。
非目标 自研内容编辑器、逐页媒体手动生成、PBL v2、ZIP 导入导出主流程。 课程编辑复用 OpenMAIC 原生能力。

4. 用户与核心场景

用户 目标 典型场景 成功标准
企业管理员 创建和管理企业课程、用户、测评、考核和看板。 通过宿主入口进入 OpenMAIC，生成课程，确认大纲，编辑课程，设置分类和可见范围，发布课程。 课程可被目标角色学员看到，学习和测评数据进入看板。
企业学员 注册、学习课程、完成课后测评和阶段考核。 用手机号、密码、邀请码注册，进入课程列表，学习课程，完成测评；不通过则重学。 学员只看到自己可学课程，测评/考核结果被准确记录。
宿主系统 提供统一入口，并在宿主侧展示培训数据。 前端 iframe 嵌入 OpenMAIC；后端用 API Key 查询课程完成率、测评和考核结果。 宿主不直连数据库、不暴露密钥，也能展示权威数据。
测试/运维 验证权限、数据一致性、接口安全和部署配置。 验证管理员/学员权限隔离、弱网缓存、OSS 上传、Host API 鉴权和 CSP/origin 配置。 核心链路可回归，异常情况有明确错误信息。

5. 假设、依赖与约束

类别 内容 影响
产品假设 首版企业内部只有一个租户，每个用户只有一个当前角色。 简化权限、课程可见范围和考核策略设计。
技术依赖 PostgreSQL、Drizzle ORM、Aliyun OSS、签名 session cookie、Host API Key/Secret。 需要先完成 SLICE-00 地基，否则后续功能会大量 mock。
复用依赖 现有大纲预览/编辑、Pro Mode / AI 编辑助手、quiz surface、gradeChoiceQuestions()、课堂播放 UI。 减少新编辑器建设，但需要加管理员权限门控。
安全约束 postMessage 必须验证 origin；Host API 密钥只允许宿主后端保存；管理 API 必须校验管理员权限。 影响 iframe、Host API、后台 API 的验收。
性能/载荷约束 课程内容 API 单次请求不超过 10MB；媒体走分片上传或预签名 URL 直传 OSS。 影响课程内容保存、媒体存储和弱网体验。

7. 关键流程

流程 步骤 完成标准
管理员建课发布 宿主 SSO 进入 OpenMAIC → 生成课程大纲 → 管理员确认/编辑大纲 → 生成完整课程 → Pro Mode / AI 编辑助手修改 → 设置分类和可见范围 → 发布。 目标角色学员课程列表可见，非目标角色不可见。
学员学习测评 手机号 + 密码 + 邀请码注册 → 进入课程列表 → 学习课程 → 完成后进入课后测评 → 通过则课程完成，不通过则查看解析并重学。 学习进度和每次测评尝试均写入后端。
阶段考核 管理员配置角色、分类、课程范围、题量和阈值 → 发布考核 → 学员参加 → 服务端抽题评分 → 结果落库。 只抽单选/多选，结果进入后台和 Host API。
宿主看板查询 宿主后端保存 API Key/Secret → 调用 OpenMAIC Host API → 查询汇总、课程进度、测评和考核结果 → 宿主前端展示。 宿主前端不暴露密钥，宿主不直连数据库。

10. 风险与缓解

风险 影响 缓解方案 关联切片
账号体系比原 ACCESS_CODE 重 开发量上升，权限改造影响面大。 首版只做手机号密码、邀请码、单角色、单租户，不做验证码和组织树。 00, 07
IndexedDB 与后端权威冲突 可能出现本地旧数据覆盖服务端新数据。 保存/发布/提交以服务端为准，本地只做草稿和缓存，冲突以服务端 updatedAt 为准。 01, 06
阶段考核题量不足 无法按策略组卷，影响考试发布。 管理端保存/发布策略时展示候选单选/多选题量，不足时阻断或提示调整。 05
Host API 密钥泄露 培训数据泄露。 密钥只允许宿主后端保存；服务端保存 hash；支持停用轮换；必要时加签名和 nonce。 00, 01
管理员后台范围膨胀 偏离首版目标，拖慢主链路。 后台仅保留看板、课程、分类、角色、邀请码、用户角色、考核策略。 07, 01, 05

11. 开放问题

问题 待确认点 建议
管理员后台 UI 归属 后台壳、菜单、首页看板、各管理页分别放入哪个 slice。 后台入口和壳放 SLICE-07；后台 API 和首页看板放 SLICE-01；考核策略页放 SLICE-05。
课程内容变更后的测评提示 提示出现在保存课程、发布课程，还是测评题编辑页。 发布课程时强提示；测评题编辑页常驻提示；不自动覆盖人工题。
考核题量不足是否阻断 候选题量不足时允许发布还是禁止发布。 建议强阻断发布，避免学员开始考试时报错。
host SSO 是否默认管理员 所有 hostUserId 是否都创建管理员，还是宿主需要额外传权限声明。 首版按当前 PRD 默认管理员；如宿主有多角色入口，再增加签名权限声明。
Host API 鉴权强度 Bearer API Key 是否足够，是否需要时间戳、签名、nonce。 涉及企业数据，建议采用 KeyId + HMAC 签名 + 时间戳，后续再评估 nonce。

12. 明确范围外

范围外事项 原因
多租户组织树部门可见指定用户可见 首版先满足单租户、单角色、按角色可见的企业培训闭环。
短信验证码找回密码复杂账号风控 避免账号体系过重，降低首版交付风险。
宿主直连数据库OpenMAIC 主动回调宿主 宿主集成首版只走查询 API，保持系统边界清晰。
PBL v2 扩展ZIP 导入导出主流程 本次二开聚焦企业课程发布、学习、测评、考核和看板。
自研内容编辑器逐页媒体手动生成 课程编辑复用 OpenMAIC 原生大纲确认、Pro Mode 和 AI 编辑助手。
