## 二次开发范围说明

本文只定义企业二开新增/改造需求，不重新定义 OpenMAIC 原生生成、课堂播放、Pro Mode、AI 编辑助手、quiz 渲染/判分等能力。可复用能力以当前代码为准。

- **OpenMAIC 内部负责**：账号、角色、邀请码、课程生成/编辑/发布、课程可见范围、学习、课后测评、阶段考核、数据看板、后端权威存储。
- **宿主系统负责**：提供进入 OpenMAIC 的入口；用 `hostUserId` 通过 SSO 映射管理员账号；用服务端 API Key 查询 OpenMAIC 数据做宿主侧看板。
- **首版部署形态**：单租户企业版，不做多租户切换；企业课程列表、课程内容、课程草稿、课程媒体、学习进度、测评和考核以后端 PostgreSQL 为唯一权威源。学员主动导入的 ZIP 本地课程是独立例外，只保存在当前浏览器 IndexedDB，不属于企业课程。

## 问题陈述

现有 OpenMAIC 适合单机轻量生成和学习，但企业培训场景还缺少：

1. 课程、媒体、作答和学习进度主要存在浏览器 IndexedDB，换账号、浏览器或设备后不可共享；企业场景要求课程列表和课程内容必须从服务端数据库读取。
2. 没有企业内部账号、角色、课程可见范围、课程发布和阶段考核管理。
3. 学员完成课程后缺少强制课后测评和阶段考核闭环。
4. 宿主系统需要统一入口和数据看板，但不应直接依赖 OpenMAIC 数据库表结构。
5. 管理员编辑课程应复用现有大纲编辑和 Pro Mode，而不是再造一套课程编辑器。

## 解决方案

将 OpenMAIC 改造为自带轻量后台的企业课程平台：

1. 管理员在 OpenMAIC 内生成课程、默认进入大纲预览/编辑，确认后生成完整课程；生成后通过 Pro Mode / AI 编辑助手修改课程。
2. OpenMAIC 新增自有账号体系。学员用手机号 + 密码 + 邀请码注册，邀请码绑定内部角色；宿主用 SSO `hostUserId` 自动注册/绑定管理员账号。
3. 管理员后台提供课程、分类、角色、邀请码、用户角色、阶段考核和精简数据看板。
4. 课程发布前设置可见范围，首版支持「全体可见」和「按角色可见」。
5. 学员登录后进入角色化学习首页，看到已发布且对自己可见的企业课程、当前浏览器本地课程和待完成阶段考核；课程生成与 AI 配置仅对管理员保留。
6. 课后测评和阶段考核首版只使用单选/多选题；阶段考核由管理员按角色、分类和课程发布。
7. 宿主系统通过服务端 API Key 查询 OpenMAIC 的看板数据；postMessage 只用于 iframe 即时通知，不作为权威数据通道。
8. 企业课程生成、后台课程管理、企业课程列表和企业课堂读取统一走 PostgreSQL；IndexedDB 仅保留浏览器运行态及学员主动导入的独立本地课程。

## 需求清单
> 稳定锚点。每条一个 REQ-ID，下游（技术设计/切片）引用这些 ID。编号一旦给出不再改，删除保留空号不复用。

### 大纲确认与管理员课程编辑

- **REQ-001** AI 生成课程大纲后，系统默认进入大纲预览/编辑阶段；用户未明确确认前，不自动继续生成完整课程或进入课堂。
- **REQ-002** 课程生成后的内容修改复用 OpenMAIC 原生 Pro Mode / AI 编辑助手与已注册的场景编辑面板，不新增独立内容预览页或自研场景内容编辑器。
- **REQ-003** Pro Mode、AI 编辑助手、保存/发布课程修改等入口仅具备课程管理权限的管理员可见可用；普通学员只能学习和作答。
- **REQ-004** 课后测评题目复用现有 quiz 题目结构和编辑能力；管理员可编辑题干、分值、选项、正确答案和解析。
- **REQ-005** 本次二开不新增逐场景「生成视频/图片」按钮、批量媒体手动触发页或内容变更后的媒体失效标记；媒体生成沿用 OpenMAIC 现有生成链路。

### OpenMAIC 自有账号、角色与后台

- **REQ-026** OpenMAIC 提供自有账号体系：学员注册时填写姓名、手机号和密码，姓名作为账号显示名；登录使用手机号 + 密码；首版不接入短信验证码。
- **REQ-027** OpenMAIC 内部维护单一角色模型，每个用户当前只有一个角色；角色用于课程可见范围、课程管理权限和阶段考核策略。
- **REQ-033** 宿主系统通过 SSO 入口传入 `hostUserId`，OpenMAIC 首次接收时自动创建/绑定管理员账号，后续同一 `hostUserId` 自动登录同一管理员账号。
- **REQ-034** 学员注册必须使用邀请码；邀请码由管理员创建，绑定一个 OpenMAIC 内部角色，可启用/停用并设置有效期。
- **REQ-035** 管理员可在 OpenMAIC 后台维护角色、邀请码、用户列表和用户当前角色；后台前端必须提供角色创建/编辑、邀请码创建/启停/过期时间维护、用户当前角色修改入口，不能只以 API 视为完成；岗位变更时管理员修改用户角色，历史学习/测评/考核记录保留提交时的角色快照。
- **REQ-036** 所有用户登录后默认进入课程列表；管理员额外看到进入后台的按钮。后台仅管理员可见，前端风格延续 OpenMAIC，保持简洁。

### 课程分类、发布与可见范围

- **REQ-037** 管理员可维护课程分类；课程草稿仅由首页课程生成链路创建，后台课程管理不提供手工创建草稿入口；AI 生成课程和编辑课程元数据时必须选择分类，分类用于后台课程管理、阶段考核和学员端企业课程筛选。
- **REQ-038** 课程生成后默认为草稿；管理员设置可见范围并点击发布后，学员才可在课程列表中看到。
- **REQ-039** 课程可见范围首版支持「全体可见」和「按角色可见」；不支持指定用户、组织树或部门可见。
- **REQ-040** 管理员发布后仍可在后台筛选课程、调整分类和可见范围、发布、下架、继续编辑或删除课程；课程列表每页展示 10 条，筛选、重置、刷新或数据减少后页码必须回到或钳制在有效范围。
- **REQ-041** 学员课程列表只展示已发布且对当前角色可见的 PostgreSQL 课程；无需导入 ZIP 或依赖当前浏览器 IndexedDB，即可跨浏览器/跨设备打开课程内容。

### 角色化学员首页与本地课程

- **REQ-049** 首页必须等待当前会话身份解析完成后再按角色渲染。管理员继续使用现有课程生成工作台；普通学员进入学习首页，不得看到课程生成输入、Agent、PPTX 导入、AI 设置或生成页入口，但保留头像、语言、主题、退出和 ZIP 本地课程导入。
- **REQ-050** 学员主动导入的 ZIP 课程只写入当前浏览器 IndexedDB，在该浏览器的所有登录账号间共享；不上传后台、不跨浏览器或设备同步、不增加 `userId` 字段或旧数据迁移。
- **REQ-051** 学员首页必须合并展示角色可见的企业课程与本地课程，并明确标记“企业课程”或“本地导入”。搜索覆盖两类课程，支持按来源筛选及加载、错误重试和空状态；企业课程只能打开，本地课程可打开、重命名和删除。
- **REQ-052** 本地课程的学习进度与测评只保存在本地，不进入企业看板、阶段考核题库、角色可见范围或任何企业课程创建、发布、进度、测评接口。
- **REQ-053** 普通学员直接访问 `/generation-preview` 时必须重定向首页；管理员仍可访问。该前端路由门控不改变 `/api/generate/*` 现有权限契约。
- **REQ-055** 系统初始化“员工手册”“公司规范规章制度”“新员工入职”三个普通可编辑分类；学员首页必须常驻展示全部后台分类作为企业课程筛选标签，即使分类下没有当前角色可见的已发布课程也不得隐藏。点击具体分类切换到企业课程并只展示匹配课程，切换到全部来源或本地课程时重置为全部分类；空分类显示“该分类暂无可学课程”。分类展示不得改变课程发布状态、角色可见范围或本地课程隔离规则。

### 课后测评与重学机制

- **REQ-006** 课程学习完成后，强制进入课后测评环节，用户必须完成测评才能标记课程为「已完成」。
- **REQ-007** 课后测评通过阈值默认为 80%，低于阈值判定为不通过。
- **REQ-008** 测评不通过时，展示错误题目解析并要求用户重新学习该课程；重新完成课程后才能再次测评。
- **REQ-009** 每次课后测评提交都记录 OpenMAIC 后端，包含通过/不通过、分数、答题详情、尝试次数和提交时角色快照。
- **REQ-042** 课后测评首版只支持单选/多选题；不使用简答题或 AI 主观评分。
- **REQ-043** 管理员修改课程内容后，系统提示课后测评题可能不匹配；管理员可手动重生成或编辑测评题，系统不自动覆盖人工编辑。

### 阶段综合考核

- **REQ-010** 阶段考核题目由 OpenMAIC 从分类课程题库中抽取组卷，题源为课内 quiz 题与课后测评题；不为考核另行 AI 生成新题。
- **REQ-011** 阶段考核结束后，将考核结果写入 OpenMAIC 后端，包含分数、通过/不通过、各题得分详情、用时、尝试次数和角色快照。
- **REQ-012** 阶段考核由 OpenMAIC 管理员配置和发布；符合目标角色的学员可在 OpenMAIC 中看到并参加。
- **REQ-028** OpenMAIC 将课程中的课内 quiz 题与课后测评题汇聚为「分类课程题库」，按课程分类和课程组织，作为阶段考核题源。
- **REQ-029** 阶段考核组卷依据管理员配置的角色、分类、课程范围、题量和通过阈值抽题，不复制题目实体所有权。
- **REQ-031** 管理员可按不同角色配置不同阶段考核策略：选择一个或多个分类，并通过可搜索的课程多选在分类下选择全部已发布课程或部分课程作为题源；空课程范围明确表示所选分类下全部课程，切换分类时恢复该语义。草稿策略可删除，已发布策略只能下架，已归档策略可重新发布；已发布和已归档策略不得删除，以保留历史考核记录。
- **REQ-032** 阶段考核和题库统计只纳入单选/多选题；课内 quiz 中的简答题必须在考核抽题时筛掉。
- **REQ-054** 学员首页以任务纸签展示当前角色已发布考核的标题、题量、通过线和时限。点击后用响应式覆盖层完成开始、单选/多选作答、提交和结果查看；未提交退出必须确认，提交失败保留答案，成功后由学员点击“完成并返回”关闭。首版不新增倒计时、历史成绩摘要或自动关闭。

### OpenMAIC 数据看板与宿主查询

- **REQ-030** 课后测评结果与阶段考核结果由 OpenMAIC 后端持久化，作为 OpenMAIC 管理后台和宿主看板查询的权威数据源。
- **REQ-044** OpenMAIC 管理后台首页为精简数据看板，必须在后台前端展示课程完成率、测评通过率、阶段考核通过率，并支持查看/筛选学员明细；学员明细每页展示 10 条，应用筛选时回到第一页，刷新或数据减少后页码钳制到有效范围；仅提供 API 不满足该需求。
- **REQ-045** 宿主系统通过 OpenMAIC 查询 API 获取看板数据；首版不要求 OpenMAIC 回调宿主系统，宿主也不直接访问 OpenMAIC 数据库。
- **REQ-046** 宿主查询 API 使用服务端 API Key/Secret 鉴权，只供宿主后端调用，不允许在宿主前端暴露密钥。

### iframe 嵌入与通信

- **REQ-013** 应用支持以 iframe 方式嵌入宿主系统，也支持独立访问。
- **REQ-014** 首版 postMessage 只保留即时通知/控制的最小闭环：`init`、`load-course`、`quiz-result`、`course-completed`、`exam-result`；如阶段考核完全由 OpenMAIC 发布，可不依赖 `start-exam`。
- **REQ-015** iframe 嵌入时隐藏 OpenMAIC 自身不必要的外框 UI，只展示功能区域内容。
- **REQ-016** postMessage 不作为登录凭证或权威数据通道；登录以 OpenMAIC 会话为准，宿主看板以查询 API 为准。

### 用户可见品牌

- **REQ-056** 登录注册、课程生成首页、管理后台、学员学习中心、课程播放与编辑、PBL 工作区、访问码弹窗、页面标题和浏览器图标等用户可见界面统一使用“元我智脑”品牌。Logo 使用 `docs/design/Logo.png` 派生的裁切透明资源，品牌文字保持可访问、可搜索，并在桌面、平板和手机宽度下稳定显示。`@openmaic/*` 包名、`openmaic_session` 等 Cookie、API 路由、签名头、数据库字段及兼容协议继续保留 OpenMAIC 技术命名。

### 后端存储服务

- **REQ-017** 新增后端存储服务，将课程列表、课程草稿、课程场景、课程大纲、课程播放所需结构、课程媒体 Blob、测评、考核、用户、角色、邀请码、可见范围、学习进度等正式业务数据持久化到 PostgreSQL。
- **REQ-018** 课程相关视频、图片、音频等媒体 Blob 全部存储到 PostgreSQL；前端通过后端鉴权接口按课程读取，不在 CHANGE-01 中引入 OSS 作为课程内容存储。
- **REQ-019** 提供 RESTful API 供前端 CRUD 课程、用户、角色、邀请码、分类、考核策略和看板数据。
- **REQ-020** 首版按单租户实现，不做租户切换；数据模型可预留 tenant 字段但不进入首版交互。

### 安全与约束

- **REQ-021** postMessage 通信必须验证消息来源（origin 白名单），防止跨域攻击。
- **REQ-022** iframe 页面设置适当的 CSP（Content-Security-Policy）头，允许被目标宿主域名嵌入。
- **REQ-023** OpenMAIC 登录会话使用服务端签名 token/cookie；管理 API 校验当前用户权限，宿主查询 API 使用 API Key/Secret。
- **REQ-024** 课程内容 API 的单次 JSON 载荷不超过 10MB；视频、图片、音频等课程媒体 Blob 写入 PostgreSQL 时必须有单条大小限制、单课程总量保护和后端流式读取能力。
- **REQ-025** IndexedDB 不再保存企业课程列表、课程草稿或企业课程内容；它仅可保存浏览器运行态、临时 UI 状态、未提交表单、播放引擎瞬时状态、必要的会话恢复标记，以及 REQ-050 定义的独立 ZIP 本地课程。
- **REQ-047** 首页课程列表、后台课程列表、课堂加载和课程发布流程必须以 PostgreSQL 数据为准；当前浏览器 IndexedDB 中存在的课程不得被视为企业课程。
- **REQ-048** 课程生成开始前必须创建 PostgreSQL 课程草稿并绑定分类；若用户未登录、无课程管理权限、分类缺失或后端写入失败，系统必须阻止进入企业课程生成主流程并给出明确错误。

## 用户故事

- 作为管理员，我要在 OpenMAIC 中生成课程并先确认大纲，以便避免错误课程结构继续生成。（REQ-001）
- 作为管理员，我要复用 Pro Mode / AI 编辑助手修改课程和测评题，以便减少重复开发的编辑器。（REQ-002, REQ-004）
- 作为管理员，我要生成课程前必须选择分类并成功创建后端草稿，以便生成中的课程能出现在后台管理并可继续发布。（REQ-037, REQ-048）
- 作为管理员，我要通过后台表单维护角色、邀请码、用户角色和课程可见范围，以便不同岗位学员看到不同课程。（REQ-034, REQ-035, REQ-039）
- 作为管理员，我要发布课程后才让学员可见，以便课程未完成时不会被误学。（REQ-038）
- 作为管理员，我要在后台首页看到学习和考核看板及明细入口，以便快速了解培训效果。（REQ-044）
- 作为学员，我要用姓名、手机号、密码和邀请码注册，以便建立可识别的个人账号并自动获得正确角色和课程列表。（REQ-026, REQ-034, REQ-041）
- 作为学员，我要在任意浏览器登录后看到同一份已发布课程列表并打开对应内容，以便不依赖本机缓存学习。（REQ-041, REQ-047）
- 作为学员，我要在首页清楚区分企业课程和当前浏览器的本地课程，并只管理本地课程，以免把个人导入内容误当成企业课程。（REQ-049~REQ-052）
- 作为学员，我要按后台维护的课程分类筛选企业课程，并能看到暂时没有可学课程的分类，以便理解完整的企业学习目录。（REQ-055）
- 作为学员，我要从首页任务纸签进入阶段考核，提交失败时保留答案，并在查看结果后主动返回，以便完成连续且可恢复的考试流程。（REQ-054）
- 作为学员，我要课后测评不通过后重新学习，以便保证培训闭环。（REQ-006~REQ-009）
- 作为宿主系统开发者，我要通过 API Key 查询 OpenMAIC 看板数据，以便在宿主系统展示统计而不直连数据库。（REQ-045, REQ-046）
- 作为平台用户，我要在登录、学习、课程和后台界面看到一致的“元我智脑”名称与 Logo，以便清楚识别当前使用的企业学习平台。（REQ-056）

## 实现决策（高层）

- 账号权威在 OpenMAIC；宿主 SSO 只负责管理员账号自动注册/绑定。
- 企业课程列表、课程草稿、课程内容、课程媒体 Blob、学习、测评、考核和看板权威数据在 OpenMAIC PostgreSQL 后端；IndexedDB 只做浏览器运行态和独立 ZIP 本地课程，不保存企业课程内容。
- 本地课程是浏览器级共享的个人导入内容，与企业课程、企业进度、企业测评、题库和看板严格隔离。
- 学员端分类标签来自后台完整分类列表；分类只缩小企业课程展示结果，不扩大课程发布或角色可见范围。
- 管理后台必须克制：只做课程、分类、角色、邀请码、用户角色、阶段考核和首页看板。
- 管理后台的“可维护/可查看”需求必须以可操作前端入口验收；API-only 只能作为下游依赖，不能单独满足管理员后台需求。
- 课程编辑不新造功能，只复用大纲编辑和 Pro Mode / AI 编辑助手，并加权限门控。
- 宿主集成首版采用查询 API，不做回调，不允许直连数据库。

## 范围外

- 不做多租户切换、组织树、部门可见、指定用户可见。
- 不做短信验证码、找回密码、复杂账号风控。
- 不做宿主数据库直连、OpenMAIC 主动回调宿主。
- 不做 PBL v2 需求扩展，不把 ZIP 导入导出纳入企业主流程。
- 不新增自研内容预览页、平行场景编辑器、逐页媒体手动生成。
- 不做阶段考核主观题/简答题 AI 评分。
- 不做本地课程账号隔离、后台上传、跨设备同步、企业看板统计或阶段考核题库汇入。
- 不做阶段考核倒计时、首页历史成绩摘要或提交成功后自动关闭覆盖层。
- 不在本次 CHANGE-01 中接入 OSS 作为课程相关内容存储；若未来需要对象存储，必须作为单独变更重新评估数据迁移、权限和备份策略。

## 备注

- 当前项目没有完整注册/登录模块，只有 `ACCESS_CODE` 访问码门禁；账号体系是新增二开能力。
- 现有 IndexedDB 表包括课程、场景、媒体 Blob、音频 Blob、播放进度、chat session、生成 agent 等；CHANGE-01 后企业课程主链路不得继续依赖 IndexedDB 课程/场景/媒体/音频记录。REQ-050 的本地课程继续复用现有 schema，并必须在首页以来源字段与企业课程区分。
- 现有 quiz 题目生成、quiz surface 编辑、`gradeChoiceQuestions()` 和 quiz 播放 UI 可复用；企业版测评/考核首版只使用单选/多选。
