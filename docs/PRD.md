# PRD：OpenMAIC 企业嵌入式课程平台
> 版本 v0.2 · 2026-06-30 · 主人文档（做什么）。下游引用本文请用 REQ-ID。
> v0.2 变更：明确二开范围；登录改为 OpenMAIC 独立登录页（账号由宿主管理）；新增角色与按角色分发考核；阶段考核题目改为从分类课程题库抽取；阶段考核/课后测评结果两边都记录。

## 二次开发范围说明
> 本 PRD **只描述与二次开发（集成/定制）相关的新增或改造需求**，不重述、不接管 OpenMAIC 原生已实现的功能。

- **原生功能（按现状复用，不在本文档定义）**：课程大纲/内容/媒体的 AI 生成引擎、quiz 题目渲染与本地判分、课堂播放（classroom）、IndexedDB 本地存储等。下游若复用这些能力，以现有代码为准。
- **二开范围（本文档定义）**：内容预览与编辑、课后测评门控、阶段综合考核、登录与角色、分类课程题库与按角色抽题、后端存储与多租户、宿主集成（嵌入/通信/数据回传）、安全约束。
- 角色划分：**学员**在 OpenMAIC 内完成全部学习与考核操作；**企业管理者**在宿主系统侧完成账号/角色管理、考核分发、结果查看。OpenMAIC 不提供管理者后台，宿主系统不承载学习过程。

## 问题陈述

企业培训系统需要 AI 自动生成课程的能力，但现有 OpenMAIC 存在以下问题：

1. **内容不可控**：大纲确认后直接生成视频，用户无法在生成前审阅/修改具体内容（文案、测验题目等），导致不满意时只能重新生成，浪费时间和算力。
2. **缺乏学习闭环**：课程学完即结束，没有课后测评验证学习效果，无法保证培训质量；缺少阶段性综合考核机制。
3. **无法集成**：作为独立应用运行，无法与企业现有培训系统打通；没有登录与角色概念，无法按企业组织/岗位分发考核；数据存在浏览器 IndexedDB 中，无法跨设备/跨用户共享，结果也无法回传企业系统。

## 解决方案

将 OpenMAIC 改造为面向**学员**的可集成课程生成与学习模块，企业**管理者**在宿主系统侧编排与管控：

1. 在大纲确认和视频生成之间插入**内容预览与编辑**步骤，视频改为用户主动触发生成。
2. 增加**课后测评**（通过才能完成课程）和**阶段综合考核**能力（由宿主管理员按角色触发）。
3. OpenMAIC **进入时需登录**，账号由宿主系统统一管理（OpenMAIC 通过独立登录页联合宿主账号服务校验），会话携带用户身份与**角色**。
4. 阶段考核题目**不另行 AI 生成**，而是从课程生成过程中产生的**课内 quiz 题**与**课后测评题**汇聚成的「**分类课程题库**」中，按管理员配置的角色策略**抽取**组卷。
5. 新增**后端存储服务**持久化课程内容；学习进度、课后测评与阶段考核结果**在 OpenMAIC 后端与宿主系统两边都记录**（OpenMAIC 持久化 + 回传宿主）。
6. 通过 **iframe + postMessage** 与服务端 API 与宿主系统集成。

## 需求清单
> 稳定锚点。每条一个 REQ-ID，下游（技术设计/切片）引用这些 ID。编号一旦给出不再改，删除保留空号不复用。

### 内容预览与编辑

- **REQ-001** 大纲确认后，系统生成各场景的详细内容（文案、测验题、互动配置），进入内容预览阶段，**不自动触发视频/媒体生成**。
- **REQ-002** 内容预览页面展示所有场景的完整内容，用户可逐场景审阅和编辑文案、测验题目/选项/答案、互动配置。
- **REQ-003** 预览页面中视频区域显示占位符，每个场景提供独立的「生成视频」按钮，用户可选择性触发单个或批量生成。
- **REQ-004** 视频生成为异步操作，生成过程中显示进度状态，不阻塞其他场景的预览和编辑。
- **REQ-005** 用户可在预览阶段反复编辑内容，编辑后对应场景的已生成视频标记为「内容已变更」，提示用户可重新生成。

### 课后测评与重学机制

- **REQ-006** 课程学习完成后，强制进入课后测评环节，用户必须完成测评才能标记课程为「已完成」。
- **REQ-007** 课后测评通过阈值为 80%，低于阈值判定为不通过，要求用户重新学习该课程。
- **REQ-008** 测评不通过时，向用户展示错误题目解析，并提供「重新学习」入口，重新学习后需再次测评。
- **REQ-009** 测评结果（通过/不通过、分数、答题详情）通过 postMessage 事件回传宿主系统，并在 OpenMAIC 后端持久化（见 REQ-030）。

### 阶段综合考核

- **REQ-010** 阶段考核题目**由 OpenMAIC 从「分类课程题库」中抽取组卷**（题源为课内 quiz 题与课后测评题，见 REQ-028），**不为考核另行 AI 生成新题**；OpenMAIC 负责渲染考核界面、计时、评分。
- **REQ-011** 综合考核结束后，将考核结果（分数、通过/不通过、各题得分详情、用时）通过 postMessage 回传宿主系统，并在 OpenMAIC 后端持久化（见 REQ-030）。
- **REQ-012** 阶段编排（哪些课程/分类组成一个阶段、何时触发、面向哪个角色）由宿主系统的**管理员触发**；OpenMAIC 负责按触发请求抽题、渲染、评分、记录与回传，不提供管理者编排界面。
- **REQ-031** 管理员在宿主系统中可按**不同角色配置不同考核策略**（题库分类范围、抽题数量、时限、通过阈值）；触发考核时 OpenMAIC 依据该策略与当前学员角色组卷。
- **REQ-032** OpenMAIC 提供查询接口，向宿主系统暴露**可用题库分类与题量统计**，供管理员在宿主侧配置角色考核策略时选择。

### 登录与角色

- **REQ-026** OpenMAIC 进入时**需要登录**；账号由宿主系统统一管理，OpenMAIC 不自行注册/管理账号密码，通过**独立登录页**联合宿主账号服务校验凭证。校验通过后建立携带用户身份的会话。
- **REQ-027** 会话身份包含**角色**信息（由宿主账号服务返回）；角色用于按角色分发/组卷阶段考核（REQ-031），并可用于区分可访问内容。
- **REQ-028** OpenMAIC 将课程生成过程中产生的**课内 quiz 题**与**课后测评题**汇聚为「分类课程题库」，**按课程/分类标签**组织，作为阶段考核抽题的题源。
- **REQ-029** 阶段考核组卷为**从题库抽取**：依据管理员配置的角色策略（分类范围、数量等）从对应分类课程题库中抽题，不复制题目实体的所有权（题目仍归属其来源课程）。

### 阶段考核与测评结果记录

- **REQ-030** 课后测评结果（REQ-009）与阶段综合考核结果（REQ-011）**两边都记录**：OpenMAIC 后端持久化一份（含学员、角色、租户、分数、明细、时间），同时通过 postMessage/接口回传宿主系统一份。

### iframe 嵌入与通信

- **REQ-013** 应用支持以 iframe 方式嵌入，通过 postMessage 协议与宿主系统双向通信。
- **REQ-014** 定义标准 postMessage 协议，包含以下事件类型：`init`（初始化配置）、`load-course`（加载课程）、`start-exam`（按策略触发阶段考核）、`retake`（重新学习）、`quiz-result`（测评结果）、`course-completed`（课程完成）、`exam-result`（考核结果）、`course-published`（课程发布）。
- **REQ-015** iframe 嵌入时隐藏 OpenMAIC 自身的导航/外框 UI，只展示功能区域内容。
- **REQ-016** 支持宿主系统通过 `init` 消息传入上下文配置（租户标识、主题色、语言等）；**用户身份的确立以登录会话为准（REQ-026），`init` 不作为登录凭证**。

### 后端存储服务

- **REQ-017** 新增后端存储服务，将课程内容（大纲、场景内容、媒体文件）持久化到服务端，替代纯浏览器 IndexedDB 存储。
- **REQ-018** 媒体文件（视频、图片、音频）存储到对象存储（兼容 S3/MinIO/OSS 协议），元数据和课程结构存储到关系型数据库（PostgreSQL/MySQL）。
- **REQ-019** 提供 RESTful API 供前端 CRUD 课程内容，支持按课程 ID 加载完整课程数据。
- **REQ-020** 存储服务需支持多租户隔离（按宿主系统传入的租户标识区分数据）。

### 安全与约束

- **REQ-021** postMessage 通信必须验证消息来源（origin 白名单），防止跨域攻击。
- **REQ-022** iframe 页面设置适当的 CSP（Content-Security-Policy）头，允许被目标宿主域名嵌入。
- **REQ-023** 后端存储 API 与登录会话使用 HMAC 签名 token 鉴权（复用并扩展现有 middleware.ts 机制），token 在登录会话中携带用户/角色/租户，由宿主账号服务校验链路签发。
- **REQ-024** 课程内容 API 的单次请求载荷不超过 10MB；媒体文件上传走分片上传或预签名 URL 直传对象存储。
- **REQ-025** 系统需在弱网环境下保证基本可用：内容编辑本地暂存，恢复网络后自动同步。

## 用户故事

- 作为**课程制作者**，我要在大纲确认后预览生成的详细内容并进行修改，以便确保课程质量后再生成视频。（关联 REQ-001, REQ-002, REQ-005）
- 作为**课程制作者**，我要能选择性地为某些场景生成视频，以便节省不必要的算力消耗。（关联 REQ-003, REQ-004）
- 作为**学员**，我要用宿主系统分配的账号登录 OpenMAIC，以便所有学习与考核都在 OpenMAIC 内完成且与我的身份关联。（关联 REQ-026, REQ-027）
- 作为**学员**，我要在课程学完后参加测评，以便验证学习效果。（关联 REQ-006）
- 作为**学员**，我要在测评不通过时看到错题解析并重新学习，以便真正掌握知识点。（关联 REQ-007, REQ-008）
- 作为**企业管理者**，我要在宿主系统中按岗位/角色配置并触发阶段综合考核，以便面向不同角色分发不同考核。（关联 REQ-012, REQ-031, REQ-032）
- 作为**企业管理者**，我要获取学员的测评和考核结果数据并在宿主系统留存，以便跟踪培训效果。（关联 REQ-009, REQ-011, REQ-030）
- 作为**企业系统开发者**，我要能将课程模块以 iframe 嵌入或通过 API 集成现有系统，并复用宿主账号体系登录，以便统一用户体验与账号管理。（关联 REQ-013, REQ-015, REQ-016, REQ-026）
- 作为**企业系统开发者**，我要通过标准协议与课程模块通信，以便控制课程加载、触发考核和获取学习数据。（关联 REQ-014）
- 作为**学员**，我要能在不同设备上继续学习同一课程，以便不受设备限制。（关联 REQ-017, REQ-019）
- 作为**运维人员**，我要确保不同企业客户的数据相互隔离，以便满足安全合规要求。（关联 REQ-020, REQ-021, REQ-023）

## 实现决策（高层）

### 集成与角色边界
- 学员侧全部操作在 OpenMAIC（嵌入或独立访问）；管理者侧操作在宿主系统。OpenMAIC 不提供管理者后台。
- 宿主 → OpenMAIC：账号/角色校验、按角色触发考核、加载课程。
- OpenMAIC → 宿主：课程发布、课后测评结果、阶段考核结果（同时在 OpenMAIC 后端留存）。

### 登录与账号
- OpenMAIC 提供独立登录页，账号与角色的权威来源是宿主账号服务；OpenMAIC 联合校验后建立会话（复用并扩展现有 HMAC token/cookie 机制，token 内编码 userId/role/tenantId）。
- OpenMAIC 不存储账号密码，不做账号注册/管理。

### 生成流程改造
- 将现有「大纲确认 → 并行生成内容+媒体」拆为「大纲确认 → 生成内容 → 预览编辑 → 按需生成媒体」。
- 视频生成从自动触发改为用户显式操作；内容生成仍使用 SSE 流式返回。

### 学习闭环与考核
- 课后测评复用现有 QuizQuestion 类型和 quiz-view 渲染组件；通过/不通过判定在前端完成。
- 阶段考核题源为「分类课程题库」（课内 quiz 题 + 课后测评题），由 OpenMAIC 按角色策略抽题组卷、渲染、评分；不为考核新生成题目。
- 课后测评与阶段考核结果两边记录：OpenMAIC 后端持久化 + 回传宿主。

### 数据持久化
- 新增后端存储层：对象存储（S3 兼容）+ 关系型数据库；前端保留 IndexedDB 作为离线缓存/草稿暂存。
- 新增考核结果与题库相关数据结构（详见技术设计）。

### 安全
- postMessage origin 白名单校验；CSP frame-ancestors 配置。
- API 与会话使用 HMAC 签名 token（复用现有 middleware 机制并扩展为用户/角色/租户）。
- 多租户通过 token 中的 tenant_id 字段隔离。

## 范围外

- **OpenMAIC 原生功能本身**：不改变课程/媒体生成引擎、quiz 判分、课堂播放等既有实现逻辑，本文档仅在其上做集成/编排层改造。
- **宿主系统开发**：不涉及宿主系统的具体实现（含管理者后台、账号服务内部实现），只定义协议与集成接口。
- **账号管理**：账号与角色的创建、维护、密码策略由宿主系统负责，OpenMAIC 仅做登录校验与会话承载。
- **阶段编排逻辑**：哪些课程/分类组成一个阶段、阶段之间的先后关系、面向哪个角色由宿主管理员决定。
- **考核出题（AI 生成）**：阶段考核不新生成题目，仅从既有分类课程题库抽取。
- **课程推荐/学习路径规划**：不做智能推荐，学习路径由宿主系统决定。
- **移动端原生适配**：仅保证 iframe 内的 Web 响应式，不做原生 App。
- **历史数据迁移**：现有 IndexedDB 中的数据不提供自动迁移到后端存储的方案。

## 备注

- 现有 quiz 系统（grading.ts、quiz-view.tsx、persistence.ts）可大量复用，课后测评主要是新增流程控制和通过/不通过门控逻辑。
- 现有登录为单一全局 `ACCESS_CODE` + HMAC cookie（middleware.ts），二开需扩展为「按用户/角色、由宿主账号服务联合校验」的登录会话。
- media-orchestrator.ts 是视频自动生成的核心，需要重构为手动触发模式。
- 分类课程题库为「视图/聚合」概念——题目实体仍属于来源课程的场景/课后测评，抽题只引用不复制所有权。
- 后端存储服务建议作为独立模块开发，可选择与 Next.js API Routes 共存或独立部署。
- postMessage 协议与集成 API 需要提供 SDK/工具库与文档供宿主系统开发者使用，降低集成成本。
