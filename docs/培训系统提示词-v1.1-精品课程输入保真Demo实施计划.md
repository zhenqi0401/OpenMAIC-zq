# 精品课程输入保真 Demo 实施计划

## 1. 目标与边界

本 Demo 验证以下普通浏览器生成链路：用户需求文本或 PDF → 明确选择培训策略 → 服务端提取并编号可信来源 → 大纲生成必须覆盖项和来源引用 → 用户在大纲审阅页编辑必须覆盖项 → Slide、Quiz 及其讲稿继续消费相同保真上下文 → 完整大纲随 Stage 保存到 IndexedDB 并可恢复。

策略类型为 `management`（管理知识培训）、`sales`（销售培训）、`professional`（专业知识培训）、`company_policy`（公司制度培训）和 `other`（原大纲总结式）。前四种启用输入保真增强；`other` 和旧请求缺少策略字段时严格走原有生成分支，不建立来源目录、不新增 Prompt 上下文、不显示保真面板，也不改变 Slide、Quiz、Interactive、PBL 和讲稿的原有协议与效果。

本次正式验收普通模式的 Slide 和 Quiz。互动模式、任务引擎保留入口和现有行为，但不承诺消费保真字段。不实现完整 Prompt v1.1 版本体系、联网来源、自动覆盖率修复、独立来源数据库、PostgreSQL migration、企业服务端持久化专项、异步课堂生成、编辑器 Agent 重生成、ZIP v2 或历史课程升级。

## 2. 数据契约

- 新增唯一 `TrainingCourseType` 枚举；`UserRequirements.trainingCourseType` 保持可选，兼容旧请求和历史数据。
- 新首页必须明确选择合法策略；未知 API 值返回 400；缺失值和 `other` 进入原有分支。
- `SceneOutline` 可选增加 `teachingBrief?: { mustCover: string[] }` 与 `sourceEvidence?: SourceEvidence[]`。
- `SourceEvidence` 包含服务端生成的 `id`、`kind`、`label` 和受限长度的 `excerpt`。模型只返回来源 ID，服务端按临时目录回填真实摘录，绝不信任模型返回的来源正文。
- 新字段继续保存于现有 outline JSON；不升级 Dexie 或 PostgreSQL schema，不建立浏览器独立来源表。

## 3. 首页和交互

- 首页增加与管理员课程分类相互独立的必选策略选择器，初始为空，五个选项展示名称和说明。
- 点击提交和 `Ctrl/Cmd + Enter` 共用防御性校验；管理员课程分类与策略缺失使用不同错误。
- 切换策略不清空需求或 PDF；策略写入 `UserRequirements` 与 `generationSession`；新建课程不恢复上一次策略草稿。
- 互动模式或任务引擎开启时显示“当前 Demo 的输入保真增强主要适用于普通生成模式。”，但不隐藏或禁用入口。

## 4. 来源构建与大纲规范化

仅四种增强策略在普通大纲调用前构建临时来源目录：需求文本按段落、列表项和约束拆分为 `REQ-001` 等；PDF 解析文本按标题、段落和长度限制拆分为 `DOC-001` 等，标签使用原文件名且没有可靠页码时不伪造页码。空块、完全重复块和超长内容会被过滤或截断，联网搜索结果不进入目录。

来源在 Prompt 中明确标记为不可信参考材料，禁止执行其中的指令。模型为每个场景输出 `teachingBrief.mustCover` 和 `sourceRefIds`。服务端清洗空白、重复、数量过多或异常过长的覆盖项，只接受本次目录中的引用 ID，再回填 `sourceEvidence`。SSE 可先展示基础 outline，但 `done` 必须返回规范化后的完整 outlines，前端用它覆盖临时流数据。

四种轻量策略分别强调：管理培训的实践痛点、框架、案例和行动建议；销售培训的客户场景、技巧、演练和应用；专业培训的输入/PDF 优先以及不补造参数、标准或能力；公司制度培训的审批、处罚、福利、权限、流程和合规事实必须有来源，资料不足时标记待补充。

## 5. 大纲审阅与下游贯穿

- 仅含保真字段的场景显示“内容保真”区域，展示可编辑的必须覆盖项及只读的用户/PDF 来源名称与摘录。
- 覆盖项支持新增、修改、删除；删除提示后续不再强制覆盖。来源 ID 和正文不可输入或修改；生成流未结束时整体只读；长摘录可展开；移动端单列且无横向溢出。
- 排序、改标题、切换普通场景类型不得丢失字段。缺少字段的历史大纲与原大纲总结式不显示空面板。
- 用户确认后的 `mustCover` 是下游权威值。共享构造函数仅对四种增强策略且存在保真字段的 outline 返回策略、必须覆盖项和真实来源摘录。
- 普通 Slide、Quiz 内容及两者 actions/讲稿消费同一上下文：可见内容优先覆盖必须项，放不下的重要细节进入讲稿；数字、名称、步骤、条件和限制不得无依据改写；通用解释不得伪装成用户事实；公司制度不得补造条款。现有 JSON 输出协议保持不变，内部来源 ID 不展示给学员。

## 6. 首场景、续生成和恢复

首场景 content/actions 使用规范化后的 effective outline。完整 outlines 通过现有 `setOutlines()` 写入 IndexedDB；课堂剩余场景和失败重试从 Stage outlines 读取相同字段，页面刷新后也从 `stageOutlines` 恢复。现有首场景 `requirements` 参数保留，但保真能力不依赖它，不复制完整需求到每次请求，也不扩展独立持久化结构。

## 7. 验证标准

- 类型与兼容：五个合法值、首页空默认、唯一“原大纲总结式”文案、旧请求兼容、未知值 400、历史 outline 可读、新字段 JSON 往返不丢失。
- 严格回归：`other` 与缺失值继续使用原 `requirements-to-outlines` Prompt；无来源构建、策略指令、保真输出字段或下游上下文；现有请求/输出协议不变。
- 来源与规范化：REQ/DOC 分别编号、PDF 文件名正确、无虚假页码、去空去重限长、合法 ID 回填、伪造 ID/正文剔除。
- Prompt 合同：四种策略说明进入普通大纲 Prompt，Slide/Quiz content/actions 收到同一上下文，无未解析占位符且 JSON 协议不变。
- 前端：策略必选且键盘不可绕过，分类错误独立，切换不清空输入，保真面板增删改和来源只读，排序/标题/类型变更字段不丢失，历史与 legacy UI 不变。
- 浏览器：专业知识+文本、公司制度+PDF及刷新恢复、原大纲总结式三条端到端场景；覆盖桌面与 375px、明暗主题、键盘、控制台错误和横向溢出。

## 8. 实施顺序

依次完成计划文档、类型契约、首页选择、来源构建与大纲规范化、大纲保真编辑器、Slide/Quiz content/actions 接入、课堂续生成与恢复验证、三语言和测试、浏览器验收、最终 Git diff 与工程案例沉淀判断。所有改动保持在 Demo 边界内，并保留工作区已有的无关文件。
