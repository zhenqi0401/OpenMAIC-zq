## 一、前端实施目标

前端不只增加一个下拉框。它必须让用户能够明确选择课程类型、理解该选择的影响，并保证这个选择在生成、恢复和重生成过程中不丢失。

本计划覆盖：

1. 首页新增必选“培训课程类型”，与管理员“课程分类”保持独立；
2. 生成按钮、键盘提交、草稿恢复都遵循课程类型必选规则；
3. 生成预览页展示服务端确认后的课程类型和策略版本；
4. 大纲审阅页展示 Opening/Core/Closing、Quiz 目的、场景教学任务书和来源状态；
5. 公司制度资料不足时显示明确的确认流程，不在客户端自行猜测资料是否充分；
6. 联网失败时降级继续生成，并在界面告知“未使用联网资料”；
7. 课堂和专业编辑器中能查看课程策略，重生成继续使用原版本；
8. 桌面、移动端、键盘、屏幕阅读器和多语言均可用。

## 二、当前前端基线

### 2.1 首页

当前 `app/page.tsx`：

- `FormState` 包含 PDF、需求文本、管理员课程分类、联网、互动和职教测试模式；
- 管理员可见“课程分类选择”；
- `canGenerate` 只依赖需求、模型和管理员课程分类；
- `handleGenerate()` 创建 `UserRequirements` 并写入 `generationSession`；
- 没有培训课程类型字段；
- 课程分类和培训课程类型的产品语义目前无法区分。

### 2.2 生成预览与大纲审阅

当前：

- `generationSession` 保存需求、PDF、联网结果、大纲和管理员分类；
- `OutlinesEditor` 可编辑标题、描述、关键点、场景类型等；
- 页面没有展示提示词策略版本；
- 页面没有展示场景是 Opening/Core/Closing；
- 页面没有展示 `teachingBrief` 或来源引用；
- 联网请求失败会直接中断当前生成流程。

### 2.3 课堂与编辑器

当前：

- 课堂从 `generationParams` 恢复 PDF 图片、Agent、语言和企业课程 ID；
- 课程类型/策略版本没有可见入口；
- 编辑器 Agent 重生成 UI 不提示“沿用原课程策略”；
- 历史课程和新版课程在界面上不可区分。

## 三、产品信息架构

### 3.1 两个字段必须明确区分

| 字段 | 用户问题 | 用途 | 是否影响 Prompt |
| --- | --- | --- | --- |
| 培训课程类型 | “这是一门什么类型的培训？” | 选择 v1.1 角色、结构、来源和时长策略 | 是 |
| 课程分类 | “课程保存到哪个管理分类？” | 管理、筛选、展示和权限业务 | 否 |

界面文案中禁止把两者都简称为“课程类型”。管理员同时看到两个字段时，应在视觉和说明上保持独立。

### 3.2 课程类型选项

| 值 | 中文名称 | 辅助说明 |
| --- | --- | --- |
| `management` | 管理知识培训 | 理论框架、企业痛点、实践案例与应用闭环 |
| `sales` | 销售培训 | ToC/ToB 场景、客户痛点、技巧和演练 |
| `professional` | 专业知识培训 | 优先依据用户输入和资料，强调专业准确性 |
| `company_policy` | 公司制度培训 | 仅依据真实制度内容生成具体条款 |
| `other` | 其他课程 | 使用当前原版提示词行为 |

默认值必须为空，不能默认选中“其他”，否则会绕过“用户明确选择”的要求。

## 四、页面改造方案

### 4.1 首页课程类型选择器

主要文件：

- `app/page.tsx`
- 建议新增 `components/generation/training-course-type-select.tsx`
- `lib/i18n/locales/zh-CN.json`
- `lib/i18n/locales/zh-TW.json`
- `lib/i18n/locales/en-US.json`

交互设计：

1. 在需求输入框下方、工具栏上方增加“培训课程类型（必选）”；
2. 管理员课程分类仍单独显示，建议两项使用并列或上下两行的紧凑字段；
3. 桌面端宽度足够时可双列，移动端必须单列；
4. 选择器显示当前选项名称，展开后显示名称和一行辅助说明；
5. `其他课程` 明确标注“使用原版提示词”；
6. 不通过需求关键词自动选择，不在上传 PDF 后自动改选；
7. 切换课程类型不会清空需求或 PDF；
8. 已开始生成后，预览页只显示服务端确认结果，不允许直接切换；如需修改，返回首页重新生成。

状态改造：

```ts
interface FormState {
  // 现有字段保持
  trainingCourseType: TrainingCourseType | '';
}
```

校验改造：

- `canGenerate` 增加 `trainingCourseType !== ''`；
- 点击按钮和 `Ctrl/Cmd + Enter` 共用同一校验；
- 未选中时在字段附近显示错误并将焦点移动到选择器；
- 不能只依赖 disabled 按钮，`handleGenerate()` 仍要防御性校验；
- 管理员缺分类与缺培训课程类型使用不同错误文案；
- 创建 `UserRequirements` 时写入课程类型，不由前端自行拼接完整 Policy。

### 4.2 草稿与本地状态

建议使用独立键保存用户最近一次明确选择，例如：

```text
trainingCourseTypeDraft
```

但恢复规则必须满足：

- 第一次使用仍为空；
- 只有用户完成过明确选择才恢复；
- 恢复后选择器仍清晰显示，不做隐藏默认；
- 不把管理员课程分类值映射为培训课程类型；
- 清除浏览器草稿时同步清除该值；
- 多标签页只把它当首页草稿，运行中的课程以 `generationSession/Stage` 为准。

如果产品坚持“每次都必须重新明确选择”，则不保存该草稿；实施前由产品确认，但无论哪种选择都不能默认静默落到 `other`。

### 4.3 生成预览页策略摘要

主要文件：

- `app/generation-preview/page.tsx`
- `app/generation-preview/types.ts`
- `app/generation-preview/components/visualizers.tsx`

在预览页标题/步骤区增加只读策略摘要：

```text
管理知识培训 · 提示词策略 v1.1
```

状态来源必须是 SSE `done` 返回的服务端规范化值，而不是只信任首页本地值。

展示规则：

- 四类新版显示“提示词策略 v1.1”；
- `other` 显示“原版提示词”；
- 历史/缺失字段按原版展示；
- 任务引擎开启时可附加“职教任务结构”，但不能覆盖课程类型标签；
- 互动模式可附加“互动模式”，三者是不同维度；
- 不在普通用户界面展示内部枚举字符串。

### 4.4 联网失败降级提示

当前浏览器搜索失败会抛错终止生成，应调整为：

1. 搜索成功：显示来源数量，`ResearchStatus = succeeded`；
2. 未开启：不显示警告，状态为 `disabled`；
3. 未配置：显示“未配置联网检索，本次仅使用用户输入和上传资料”，继续生成；
4. 调用失败：显示可关闭的非阻断警告“联网检索失败，本次不会引用联网资料”，继续生成；
5. 不显示“正在使用权威资料”等未经验证的描述；
6. 管理/销售在无来源时，预览说明案例将按模拟情境生成；
7. 公司制度不能用联网结果替代真实公司制度材料。

错误提示要区分“联网降级”与“模型/大纲生成失败”，避免用户误以为整个课程失败。

### 4.5 公司制度资料不足确认

触发条件必须来自服务端来源注册结果，例如：

```text
trainingCourseType = company_policy
且 requirement/document 类型的有效来源块为 0
```

不能只在客户端用“是否上传 PDF”“需求字符数”判断，因为用户可能已在文本框粘贴制度内容，PDF 也可能解析为空。

服务端返回结构化状态：

```ts
sourceReadiness: 'ready' | 'framework-only-confirmation-required';
```

前端弹窗提供：

- 主操作：“返回补充制度资料”；
- 次操作：“仅生成培训框架”；
- 说明：不会生成具体审批、处罚、福利、权限或合规条款；
- 取消：留在当前页，不开始内容生成。

用户选择“仅生成培训框架”后，需要把显式确认写入本次生成会话，例如 `allowFrameworkOnly: true`，并由服务端再次校验；不能只关闭弹窗继续发送原请求。

### 4.6 大纲审阅增强

主要文件：

- `components/generation/outlines-editor.tsx`
- 可新增 `components/generation/source-reference-list.tsx`
- 可新增 `components/generation/teaching-brief-editor.tsx`

每个场景卡片增加以下可折叠信息：

- `courseSection` 标签：开始引导 / 核心讲解 / 结尾应用；
- Quiz `purpose`：随堂检查 / 综合复习；
- 必须讲解 `mustCover`；
- 支撑细节 `supportingDetails`；
- 应用目标 `applicationFocus`；
- 用户限制 `userConstraints`；
- 来源标签：用户需求 / 上传资料 / 联网来源；
- 可用时显示文件名、页码、网页标题和链接。

编辑规则：

- 课程结构和教学任务书允许用户审阅和编辑；
- 来源引用只能从服务端提供的来源目录中选择，不能自由输入任意 ID；
- 删除 `mustCover` 时提示它会从后续内容覆盖要求中移除；
- 修改场景类型时保留通用任务书和有效来源，只清理场景类型专属配置；
- 拖拽排序后保留 `courseSection`，但若三层顺序被破坏应显示警告，不自动偷偷改回；
- SSE 流式阶段继续只读，完成后才允许编辑；
- `other + legacy` 不强制显示 v1.1 专属字段，避免原版课程界面噪声。

### 4.7 来源详情和安全显示

- 来源正文默认折叠，只显示短摘录；
- URL 使用安全链接属性并只允许 `http/https`；
- 不渲染来源中的 HTML；
- 不把来源文本当 Markdown 指令执行；
- 长文本截断并提供展开，不制造横向滚动；
- 被服务端剔除的来源显示“引用已失效”，不再发送给下游；
- 联网来源和“模拟案例”使用明显不同的标签，避免用户误认为模拟内容是真实事实。

### 4.8 课堂页和专业编辑器

主要文件：

- `app/classroom/[id]/page.tsx`
- `components/stage/header-controls.tsx` 或实际课程信息入口
- 编辑器课程信息/Agent 重生成相关组件

建议在课程信息菜单而非主播放画面常驻展示：

- 培训课程类型；
- 提示词策略版本；
- 互动/任务引擎状态；
- 来源状态摘要。

重生成交互：

- 全量 Slide 重生成和讲稿重生成卡片显示“将沿用本课程 v1.1/原版策略”；
- 不提供在单个场景临时切换策略版本的控件；
- 历史课程显示“原版策略”；
- v1.1 课程来源缺失或引用失效时，在重生成前警告；
- 现有“还原到重生成前”能力保持不变；
- 学员播放界面不展示内部 Prompt 或全部来源正文，避免干扰学习体验。

## 五、组件和状态设计

### 5.1 建议组件

```text
components/generation/
  training-course-type-select.tsx
  course-policy-summary.tsx
  source-readiness-dialog.tsx
  source-reference-list.tsx
  teaching-brief-editor.tsx
```

原则：

- 选项元数据使用共享常量，不在多个组件重复中文名称；
- 业务枚举与 i18n 显示文本分离；
- 选择器只产生课程类型，不在组件里计算策略；
- 策略摘要消费服务端规范化结果；
- 来源对话框消费结构化错误/状态码，不解析错误字符串。

### 5.2 会话状态

扩展 `GenerationSessionState`：

```ts
interface GenerationSessionState {
  // 现有字段保持
  trainingCourseType?: TrainingCourseType;
  promptPolicyVersion?: PromptPolicyVersion;
  researchStatus?: ResearchStatus;
  sourceCatalog?: SourceCatalogEntry[];
  sourceReadiness?: 'ready' | 'framework-only-confirmation-required';
  allowFrameworkOnly?: boolean;
}
```

`trainingCourseType` 可同时存在于 `requirements` 和规范化上下文中，但必须明确单一权威：

- 发送请求前：用户表单值；
- SSE `done` 后：服务端规范化值；
- Stage 创建后：Stage 持久化值；
- 重新打开或重生成：Stage 值优先于 sessionStorage。

### 5.3 API 错误合同

前端依赖以下结构化错误/状态，不应匹配英文错误字符串：

| code | 前端行为 |
| --- | --- |
| `INVALID_TRAINING_COURSE_TYPE` | 返回首页并聚焦课程类型 |
| `INVALID_PROMPT_POLICY_VERSION` | 阻止生成，提示刷新/联系管理员 |
| `PROMPT_POLICY_MISMATCH` | 阻止生成，不自动改版本 |
| `SOURCE_CONFIRMATION_REQUIRED` | 打开制度资料不足弹窗 |
| `SOURCE_REFERENCE_INVALID` | 大纲引用标记失效并要求重新确认 |
| `RESEARCH_DEGRADED` | 非阻断提示并继续生成 |

具体错误码可在实施时按仓库现有 API 命名规范调整，但服务端和前端测试必须锁定同一合同。

## 八、测试与浏览器验收

### 8.1 组件/单元测试

- 五个选项值、显示名和辅助说明正确；
- 默认无选项；
- 未选不能提交，错误后焦点正确；
- 课程分类和课程类型互不改变；
- `other` 明确显示原版提示词；

- 公司制度无来源弹窗三个操作正确；

- 历史 Stage 显示原版策略；
- 重生成工具卡显示沿用版本。

### 8.2 E2E 场景

1. 普通用户选择管理培训后生成，预览和课堂均显示管理 + v1.1；
2. 管理员同时选择课程分类和销售培训，二者独立保存；
3. 未选课程类型时按钮不可用，键盘提交也不绕过；
4. 选择其他课程，显示原版策略且无三层结构强制提示；
5. 专业知识 + PDF：大纲审阅能看到资料引用；
6. 公司制度 + 有效资料：直接进入正常审阅；
7. 公司制度 + 无有效资料：必须确认框架模式或返回；
8. 联网开启但失败：出现降级提示并继续，不出现伪造来源；
9. 大纲拖拽、修改类型和删除来源后数据保持一致；
10. 刷新预览页、进入课堂后刷新、重新打开课程，策略仍一致；
11. 编辑器重生成 Slide/讲稿时沿用保存版本；
12. 旧课程打开后显示原版策略，不要求补选类型；
13. 移动端选择器、弹窗、大纲来源区无横向滚动；
14. 三种语言均无原始 i18n key 泄露。

## 九、验收标准

### 9.1 首页

- 所有用户生成前必须明确选择培训课程类型；
- “课程分类”与“培训课程类型”文案、状态和保存逻辑独立；
- 未选择不能通过点击或快捷键提交；
- `其他课程` 明确说明使用原版提示词。

### 9.2 预览与来源

- 显示服务端确认后的类型和版本；
- 管理/销售可见三层结构信息；
- 专业/制度可见任务书和可信来源；
- 未知来源不能由用户手输绕过；
- 联网失败继续生成并明确显示未使用联网资料；
- 无来源真实案例和模拟案例能被用户区分。

### 9.3 制度课程

- 有真实制度来源时正常生成；
- 无来源时不能静默生成具体公司条款；
- 用户只能返回补资料或显式确认框架模式；
- 确认动作由服务端再次校验。

### 9.4 恢复与重生成

- 刷新、失败重试、课堂续生成和重新打开后策略不变；
- 编辑器重生成沿用 Stage 保存版本；
- 历史课程按 legacy 打开，不弹出新建课程必选流程；
- 学员播放主界面不暴露内部 Prompt 内容。

## 十、风险与防复发措施

| 风险 | 防复发措施 |
| --- | --- |
| 只加选择器，后续场景丢类型 | E2E 覆盖首场景、剩余场景、刷新和重生成 |
| 把管理员分类当提示词类型 | 组件、字段、文案和测试完全分离 |
| 客户端展示值与服务端实际策略不同 | SSE `done` 后以服务端规范化值为权威 |
| 搜索失败导致课程整体失败 | 独立 `ResearchStatus` 和非阻断降级状态 |
| 客户端误判制度资料是否充分 | 只消费服务端 `sourceReadiness` |
| 用户自由输入伪造来源 ID | 来源选择器只能使用服务端目录 |
| v1.1 界面污染旧课程 | legacy 条件渲染和历史 Stage E2E |
| 移动端大纲详情过宽 | 折叠详情、单列布局和 320/375 宽度验收 |
| 新文案遗漏翻译 | 三语言资源 + `check:i18n-keys` |

## 十一、前端完成定义

前端工作只有在以下条件全部满足时才算完成：

- 首页课程类型必选项已上线并与管理员分类独立；
- 预览、课堂、恢复和重生成显示并沿用服务端策略；
- 联网失败能够可见降级继续生成；
- 制度资料不足有服务端驱动的确认流程；
- v1.1 大纲可审阅教学任务书和可信来源；
- legacy 课程不被强制升级或增加不必要操作；
- 三语言、键盘、移动端、暗色模式均通过验收；
- 相关单元测试、E2E、i18n 检查、格式检查和 webpack 构建均有可复核结果。
